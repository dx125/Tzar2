# Tzar2

A rebuild of the real-time strategy game *TZAR: The Burden of the Crown* (Haemimont, 2000) on a modern stack: a
deterministic, engine-independent C# simulation core and a Godot 4.7 .NET client. Tzar2 is a codename; the public name
is not decided. Release 1.0 targets Windows x64; other platforms follow later (DEC-14).

The binding specification is the [Technical Design Document](docs/TDD.md). Decisions made while implementing it are in
[`docs/decisions/`](docs/decisions/).

## Legal

This repository contains **no original game files** and must never contain any: no executables, data, sprites, sounds,
music, maps or campaigns, and nothing extracted or converted from them (REQ-LEGAL-01). The game and its assets belong
to their rights holders. To play or to do research you need your own copy (GOG, Steam or CD). Keep it in the
git-ignored `Origin/` folder or point `TZAR2_ORIGINAL_PATH` at it. Only file manifests (paths, sizes, hashes) are
committed, see [`docs/original-build/README.md`](docs/original-build/README.md). CI fails if a tracked file matches a
file of the original game. The code is MIT-licensed ([LICENSE](LICENSE)).

## Requirements

* [.NET SDK 10.0.402](https://dotnet.microsoft.com/download) (pinned in `global.json`) and the .NET 8 runtime.
* For the client: [Godot 4.7.2 .NET](https://godotengine.org/download) (only to run or edit it; `dotnet build` works
  without it).

## Build and test

```sh
dotnet build Tzar2.sln                 # everything, including the Godot client
dotnet test Tzar2.sln                  # all test projects
dotnet build Tzar2.Headless.slnf       # everything except the Godot client
dotnet test tests/Tzar2.Determinism.Tests
dotnet run -c Release --project tests/Tzar2.Benchmarks -- --filter "*"
```

Check a local original install against the GOG v1.10 English reference build (TDD REQ-RE-03):

```sh
dotnet run --project src/Tzar2.Tools.Cli -- verify-original Origin
```

Open or run the client:

```sh
godot --path src/Tzar2.Client                                   # editor
godot --headless --path src/Tzar2.Client --build-solutions --quit
```

The client's M1 mode is the **asset viewer** (sprites in the eight player colours with shadows and building overlays,
terrain transitions and water, fonts, sounds, MIDI music; [ADR 0020](docs/decisions/0020-m1-asset-viewer.md)). It needs
a package imported from your own copy of the game; without one it shows how to make it:

```sh
dotnet run --project src/Tzar2.Tools.Cli -- import <Tzar install> <out>   # writes <out>/base.original.t2pkg
godot --path src/Tzar2.Client -- --package <out>/base.original.t2pkg      # or choose it in the window
tools/soundfont/fetch-soundfont.sh                                        # optional: SoundFont for MIDI (not committed)
```

Other options: `--soundfont <sf2>`, `--select <IMAGES.INI entry>`, `--smoke` (load all and exit), `--capture <dir>`
(screenshot set; it shows original art, so keep it out of the repository). Mouse wheel zooms in integer steps,
right/middle drag or arrow keys pan, Home resets, Space pauses.

Measurements of the original game (TDD §22.3) come from the **capture harness** ([ADR 0030](docs/decisions/0030-capture-harness.md)):
on a Windows PC with the game, `pwsh tools/capture/run-capture.ps1 -TzarPath <Tzar install>` produces one zip
([operator instructions](tools/capture/README.md)); `t2 fidelity analyze <zip> --original <install>` turns it into
fact files in `tests/fidelity/facts/`.

Gameplay rules are compiled from YAML ([ADR 0031](docs/decisions/0031-rules-yaml-layers-templates-and-patches.md)):
the `classic` ruleset (`content/engine/rules/classic.yaml`) maps the tables imported from your copy of the game onto
traits and holds no original numbers ([ADR 0032](docs/decisions/0032-classic-ruleset-from-the-imported-tables.md));
values the tables do not contain are marked `UNVERIFIED` and listed in
[docs/mechanics/m2-placeholders.md](docs/mechanics/m2-placeholders.md). Tests and benchmarks compile it from synthetic
tables. `t2 bench --scenario gameplay` runs economy and combat at scale
([ADR 0039](docs/decisions/0039-gameplay-commands-scenario-and-golden-hashes.md)).

The trigonometry lookup tables in `src/Tzar2.Core/Numerics/TrigTables.g.cs` are generated by
`dotnet run --project tools/Tzar2.Tools.LutGen` (then update the hashes in `tests/Tzar2.Core.Tests/Numerics/TrigTests.cs`).

## Layout

```
content/engine/      engine-default package: the built-in rulesets (YAML, no original data)
docs/                TDD, appendices, ADRs (decisions/), mechanics/ (gameplay specs, placeholders), original-build manifests
src/
  Tzar2.Core/        fixed-point math, integer trig, deterministic RNG, xxHash64 state hashing, IDs, binary I/O
  Tzar2.Formats/     legacy format decoders (M1)
  Tzar2.Content/     VFS, packages, rules (M1-M3)
  Tzar2.Import/      import pipeline, edition verification (verify-original)
  Tzar2.Sim/         deterministic simulation (M2)
  Tzar2.Scripting/   legacy triggers, Lua (M4, M8)
  Tzar2.AI/          legacy AI DSL (M3)
  Tzar2.Net/         lockstep networking (M6)
  Tzar2.Replay/      replays (M6)
  Tzar2.Game/        match/session/campaign orchestration
  Tzar2.Server/      relay and lobby service (M6)
  Tzar2.Tools.Cli/   the `t2` tool
  Tzar2.Analyzers/   Roslyn analyzers enforcing determinism (T2D001-T2D006)
  Tzar2.Client/      Godot 4.7 .NET project
tests/               one test project per assembly, Architecture, Determinism, Benchmarks
tools/               LUT generator, CI scripts, RE prototypes (re/), SoundFont download (soundfont/), capture harness (capture/)
spikes/              M0 spikes S1-S6
```

Dependency rules between the assemblies (TDD §7.2) are enforced by `tests/Tzar2.Architecture.Tests`. Assemblies
marked `Tzar2Deterministic` (Core, Sim, Scripting, AI, Replay) fail to build if they use floating point, wall-clock
time, `System.Random`, unordered `Dictionary`/`HashSet` iteration or runtime code generation; Sim, Scripting and AI
also may not do file or network I/O ([ADR 0004](docs/decisions/0004-determinism-analyzers.md)).
